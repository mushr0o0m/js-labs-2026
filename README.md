# Лабораторные работы по JavaScript и TypeScript

Нужен Node.js 22.6 или новее. Библиотек и внешних зависимостей нет. TypeScript запускается встроенными средствами Node.js с флагом `--experimental-strip-types`.

## Запуск

Из корня репозитория:

```bash
npm start
```

Корневой файл последовательно запускает обе лабораторные без меню выбора. Сначала программа запрашивает массив чисел, число для поиска и строку со скобками для первой работы. Затем запускается лабораторная с кучей.

Общий файл запуска - `index.js` в корне. Для следующих лабораторных можно добавить вызовы `await import()` их файлов в корневой файл. Каждый такой вызов дожидается завершения предыдущей работы.

## Знакомство с ЯП TS/JS

Реализация на JavaScript находится в `labs/js-basics`.

### Сортировка

Сортировка вставками по возрастанию: каждый очередной элемент вставляется в нужное место среди уже отсортированных элементов слева. Исходный массив не изменяется.

### Бинарный поиск

Поиск работает в массиве, отсортированном по возрастанию. На каждом шаге проверяется середина оставшегося диапазона, затем отбрасывается половина диапазона.

В бинарный поиск передаётся массив, полученный после сортировки. Если число отсутствует, функция возвращает `-1`.

### Проверка скобок

Используется стек. Открывающая скобка добавляется в стек. Закрывающая должна соответствовать последней открывающей. В конце стек должен быть пустым.

| Ввод | Результат |
| --- | --- |
| `({})` | Корректный |
| `()[]<>{}` | Корректный |
| `<{[()]}>` | Корректный |
| `({)}` | Некорректный |
| `)(` | Некорректный |
| `(()` | Некорректный |

Пустая строка считается сбалансированной. Пробельные символы игнорируются. Любые другие символы, кроме скобок, делают ввод некорректным.

### Сложность

`n` - число элементов массива или длина строки. Big O описывает рост затрат при увеличении `n`, а не точное время в секундах.

| Алгоритм | Лучшее время | Среднее время | Худшее время | Дополнительная память |
| --- | --- | --- | --- | --- |
| Сортировка вставками | O(n) | O(n²) | O(n²) | O(n) |
| Бинарный поиск | O(1) | O(log n) | O(log n) | O(1) |
| Проверка скобок | O(1) | O(n) | O(n) | O(n) |

У сортировки во вложенных проходах может быть до `1 + 2 + ... + (n - 1)` сдвигов, то есть O(n²). Для уже отсортированного массива достаточно одного прохода - O(n). Копия входного массива занимает O(n) памяти, сами вставки требуют O(1).

У бинарного поиска диапазон каждый раз уменьшается вдвое, поэтому нужно не более порядка `log₂(n)` шагов. Несколько индексов занимают O(1) памяти. Время указано для самой функции поиска. Предварительная сортировка рассматривается отдельно и в худшем случае занимает O(n²).

Проверка скобок просматривает строку один раз - O(n). В худшем случае все символы являются открывающими скобками и попадают в стек - O(n) памяти. Если первый символ - закрывающая скобка, результат известен сразу - O(1).

## Пирамидальная сортировка и Priority Queue

Реализация на TypeScript находится в `labs/heap`. Отдельный запуск:

```bash
npm run lab:heap
```

Программа запрашивает массив чисел и k, затем выводит результат сортировки, k наибольших и k наименьших элементов и пример работы очереди.

### Пирамидальная сортировка

Массив представляется двоичной кучей. Для элемента с индексом i дети находятся по индексам `2 * i + 1` и `2 * i + 2`. В максимальной куче родитель не меньше своих детей.

Сначала строится максимальная куча. Затем её корень меняется местами с последним элементом неотсортированной части. Эта часть уменьшается на один элемент, а новый корень просеивается вниз. В результате получается массив по возрастанию. Исходный массив не изменяется.

### Топ-k сверху и снизу

Для k наибольших элементов используется минимальная куча. В неё добавляется очередное число. Если элементов стало больше k, минимальный удаляется. В конце остаются k наибольших чисел. Они возвращаются по убыванию.

Для k наименьших элементов используется максимальная куча. При переполнении удаляется максимальный элемент. Результат возвращается по возрастанию.

Например, для массива `5 1 9 3 9 -2` и k = 3 результат сверху - `9 9 5`, снизу - `-2 1 3`. Повторы учитываются. k должно быть целым числом от 0 до длины массива. При k = 0 результат - пустой массив.

### Priority Queue

Числовая очередь реализована на двоичной куче. По умолчанию больший элемент имеет больший приоритет. `new PriorityQueue(true)` создаёт очередь с приоритетом меньшего элемента.

| Операция | Действие |
| --- | --- |
| `enqueue(value)` | Добавить число и просеять его вверх |
| `peek()` | Получить приоритетный элемент без удаления |
| `dequeue()` | Извлечь приоритетный элемент и восстановить кучу |
| `size` | Получить количество элементов |

У пустой очереди `peek()` и `dequeue()` возвращают `undefined`.

### Сложность

| Алгоритм или операция | Время | Дополнительная память |
| --- | --- | --- |
| Пирамидальная сортировка | O(n log n) | O(n) с учётом копии массива |
| Топ-k сверху или снизу | O(n log(k + 1)) при k > 0 | O(k) |
| `enqueue` | O(log n) | O(1) без учёта хранения очереди |
| `dequeue` | O(log n) | O(1) |
| `peek`, `size` | O(1) | O(1) |
