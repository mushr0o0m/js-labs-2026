# Словарь языка

Реализация на TypeScript находится в `dictionary.ts`. Внешних библиотек нет. Отдельный запуск:

```bash
npm run lab:dictionary
```

## Структура данных

Используется префиксное дерево, или trie. Каждый переход соответствует одному символу. Слова с общим началом используют одну и ту же цепочку узлов. Полные строки слов отдельно не сохраняются.

| Метод | Действие |
| --- | --- |
| `add(word)` | Добавляет одно слово |
| `addWords(words)` | Добавляет список слов |
| `has(word)` | Проверяет наличие полного слова |


## Обозначения

- N - количество различных слов.
- S - сумма длин различных слов.
- L - длина добавляемого или искомого слова.
- T - сумма длин слов во входном списке, включая повторы.
- P - количество различных непустых префиксов всех слов.
- V = P + 1 - количество узлов с учётом корня.
- A - размер алфавита, например 33 для русских букв.

## Потребление памяти

Каждому различному непустому префиксу соответствует один узел и один входящий переход. Поэтому в структуре ровно V узлов, V объектов `Map`, V признаков конца слова и P записей переходов. Выполняется P ≤ S.

Память структуры - O(P + 1), в худшем случае O(S + 1). Если средняя длина слова равна Lср, то S = N · Lср и оценка составляет O(N · Lср + 1). Общие префиксы уменьшают фактическое число узлов.

### Ведущие множители

При хранении фиксированного массива из A переходов в каждом узле потребовалось бы A · V ячеек ссылок. Для русского алфавита это 33 · V, хотя большинство ссылок могли бы быть пустыми. В моей текущвй реализации хранятся только P существующих переходов. Однако каждая запись `Map` содержит ключ, ссылку на дочерний узел и служебные данные.

Обозначим стоимость узла вместе с его `Map` и признаком конца слова как Cузла, а стоимость одной записи перехода как Cперехода. Тогда модель памяти:

`M ≈ Cузла · (P + 1) + Cперехода · P`.

Размеры этих констант в байтах зависят от движка JavaScript, внутренней ёмкости `Map` и представления строк. Поэтому замена 33 ячеек на существующие переходы не означает уменьшение реальной памяти ровно в 33 раза и не гарантирует, что trie всегда компактнее массива строк.

Пример: «кот», «котик», «кошка» содержат 13 букв суммарно, но имеют 8 различных непустых префиксов. Получается 9 узлов и 8 записей переходов. Для фиксированного массива по 33 перехода в каждом узле потребовалось бы 33 · 9 = 297 ячеек ссылок. Это сравнение количества переходов, а не полного размера объектов в байтах.

## Скорость работы

| Метод | Время | Дополнительная память |
| --- | --- | --- |
| `add(word)` | O(L) | До O(L) новых узлов и переходов |
| `addWords(words)` | O(B + T), где B - число слов в списке | До O(T) новых узлов и переходов |
| `has(word)` | O(L), лучший случай O(1) | O(1) |

Оценки используют обычную модель среднего O(1) для обращения к `Map`. При фиксированном алфавите из A символов число переходов одного узла ограничено A. Отдельного цикла по всем 33 буквам в реализации нет.

В `add` для слова длины L выполняется L вызовов `Map.get`, не более L вызовов `Map.set` и не более L созданий узлов. Если всё слово уже существует, новые узлы не создаются. Ведущий множитель работы с таблицей - до 2L обращений: L чтений и L записей.

В `has` выполняется не более L вызовов `Map.get` и одна проверка `isWord`, то есть до L + 1 основных обращений. При отсутствии первого перехода поиск завершается сразу. При добавлении списка выполняется B вызовов `add` и до 2T обращений к таблицам. Сам входной список в оценку дополнительной памяти структуры не включён.
